# 實行紀錄：修復幽靈帳號自動清除機制異步競爭危害

本份文件紀錄了為解決連線初期的時間差誤判，所導入的帳戶時間戳記與安全緩衝期 (Grace Period) 保護機制的具體實踐成果。

## 執行變更

### 設立防護時間防線 (`script.js`, `admin.js`)
1. **連線活動時間記號**：
   - 在使用者完成登入與更新個人資料庫時，寫入 `lastActive: Date.now()`。
2. **緩衝期過濾機制**：
   - 重構了管理員自動清道夫的判斷條件。
   - 在名單處理中，若發現匿名帳號未連線 (`!onlinePresence[uid]`)，前端會秒速將其自名單中過濾隱藏。
   - 為防範連線初期 `users` 廣播抵達比 WebSocket 握手快數十毫秒所造成的秒殺誤判，系統嚴格規定必須斷線超過 10 秒以上 (`Date.now() - lastActive > 10000`)，才會發動 `remove()` 清理資料庫。

## 驗證結果
- 經由 GitHub Actions 順利完成雲端建置並推送至測試站台。
- 新進匿名帳號連線平穩順暢，秒速呈現專屬動物名稱，徹底消除了短暫降級為 Legacy User 的異步競爭現象。
